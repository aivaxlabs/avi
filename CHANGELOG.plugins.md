# Avi Plugin API Changelog

## [Canary]

### Added
- **Inbox questionnaires** — `BotPendencyMessage` can include `questions` (bot messages) or `questionMessageId` with `answers` (user messages). `bot.inbox.reply(pendencyId, { content, attachments?, questionMessageId?, answers? })` answers a questionnaire once, and the answers are validated against the stored questions. Choice limits are 10 (`single_choice`) and 30 (`multiple_choice`). Compatibility: Backward compatible; supports API v2.
- **Action pages** — new `actionPages.register` capability and `avi.actionPages.register({ id, title, kind: 'html' | 'native', icon?, load, invokeAction? })` add Activity Bar pages exposed as `plugin:<plugin-id>:<id>`. `icon` accepts a Lucide name or `{ svg }`; HTML pages return `{ html }` and call `window.avi.invoke(action, input)` from a sandboxed iframe; native pages return auxiliary panel sections. The handle exposes `refresh()` and `dispose()`. Compatibility: Backward compatible; supports API v2.
- **Context item creation time** — `ContextItem` returned by `avi.context.items.list()` includes `createdAt` (ISO string or null). Compatibility: Backward compatible; supports API v2.
- **Context item visibility** — `ContextItem` returned by `avi.context.items.list()` includes `visibility` (`private` for items under `.agents/.user-private`, otherwise `default`). Compatibility: Backward compatible; supports API v2.
- **Per-bot tool permissions** — bot create/update and snapshots accept `permissionMode: 'approve_for_me' | 'full_access'`, defaulting to `approve_for_me` for new/migrated bots and invalid values. Full access skips automatic tool approvals for new bot-managed turns; existing approvals remain pending. Compatibility: Backward compatible; supports API v2.
- **Custom JSON provider fields and model configuration** — provider type descriptor fields accept `type: 'json'`, rendered as a multiline editor and validated as a JSON object string during normalization. `ModelConfig` accepts optional `customJson` with the same validation. Built-in request formats merge provider then model custom JSON recursively into request bodies; plugin provider types receive both values and choose whether to apply them. Compatibility: Backward compatible; supports API v2.
- **Provider model listing** — provider type descriptors accept optional `supportsModelListing`; when true, the type must implement `listAvailableModels({ provider, services })` returning `Array<{ id }>`, otherwise registration fails with `VALIDATION_FAILED`. `types.list()` returns `supportsModelListing` as a boolean, and provider handles expose `listAvailableModels()` under `providers.read`. Omitting the flag keeps the previous behavior. Compatibility: Backward compatible; supports API v2.
- **Bot-authored Inbox messages** — `bot.inbox.list()` can return `BotPendencyMessage` items with `role: 'agent'` and `sender: { botId, name }` when another bot replied through cross-bot Inbox access. `bot.inbox.reply()` still records user replies and ignores fields other than `content` and `attachments`. Compatibility: Backward compatible; supports API v2.
- **Per-model media size limit** — `ModelConfig` accepts optional `mediaSizeLimit` (`5242880`, `10485760`, `20971520`, `104857600`, or `null` for no limit); omitting it inherits the global Tuning limit. Other values fail provider normalization. Compatibility: Backward compatible; supports API v2.
- **Provider harness capabilities** — provider type descriptors accept optional `harness` (`session`, `retries`, `compaction`, `instructions`, `toolExecution`); `types.list()` returns the normalized object. Stateful providers may implement `releaseSession({ provider, conversationId, reason, services })`, which Avi calls after compaction, and static provider contributions accept that handler. Providers declaring `retries: 'provider'` get one attempt in normal chats. Tool execution and compaction can only be `avi`; unknown capabilities or values fail registration. Omitting `harness` keeps the previous behavior. Compatibility: Backward compatible; supports API v2.
- **Provider streaming state and managed login input** — `eventsFrom(payload, state)` receives isolated per-attempt parser state; managed connections can request a masked secret field, such as an authorization code or API key, and a secondary action. Existing handlers remain valid. Compatibility: Backward compatible; supports API v2.
- **Bot execution-mode override** — bot create/update and persisted snapshots accept nullable `executionMode` (`direct` or `orchestrator`); null inherits the existing global bot preference. Compatibility: Backward compatible; supports API v2.
- **Inbox message metadata** — persisted bot messages expose optional `requiresUserResponse` (legacy default true) and `readAt` fields. Desktop viewing clears attention only for informational messages, without completing the conversation or resolving approvals. Compatibility: Backward compatible; supports API v2.
- Built-in plugin distribution uses the ordinary plugin lifecycle with immutable bundled sources, default-disabled enablement and reserved IDs. Management inventory exposes `builtIn` and `builtInPluginsDir`; installed plugins retain their existing lifecycle. Compatibility: Backward compatible; supports API v2.
- **Static keyboard shortcuts** — `contributions.shortcuts` accepts titled patterns, optional global support, and main-process `execute` handlers; user overrides and plugin provenance appear in Settings. Compatibility: Backward compatible; supports API v2.
- **Selectable next bot queue item** — `bot.update({ workQueueIndex })` selects the zero-based Work queue item used by the next activation. Compatibility: Backward compatible; supports API v2.
- **Per-tool forced truncation** — static and runtime tool definitions can set `forcedTruncationLength` as a positive estimated-token output limit that overrides the global tool-output setting. Compatibility: Backward compatible; supports API v2.
- **Theme transparent surfaces** — theme CSS can define `--background-transparent-0` through `--background-transparent-5` for the native Sidebar transparency mode. Compatibility: Backward compatible; supports API v2.
- **Child Processes reference plugin** — demonstrates trusted Node.js process supervision using existing Plugin API v2 storage, panels, settings, and lifecycle APIs; no public API surface was added. Compatibility: Backward compatible; supports API v2.
- **Declarative plugin settings** — plugin definitions can add Avi-rendered settings sections backed by JSON Schema and main-process `getValue`, optional `validate`, and `setValue` handlers. Compatibility: Backward compatible; supports API v2.

### Changed
- **Queued bot deliveries** — `bot.inbox.reply()` resolves to `{ item, queued, queueItemId }` and `bot.approvals.resolve()` to `{ resolved, queued, queueItemId, pendencyId }`; both add the update to the bot's priority queue instead of sending it to the main thread, and the `delivered`/`error` fields are removed. `bot.activate()` on a working bot queues the activation to start right after the current run. `BotSnapshot` adds `priorityAutoContinue`, `lastActivationKind`, and `lastActivationAt`, and `bot.update({ priorityAutoContinue })` is accepted. Compatibility: Breaking in API v2's Canary bot-delivery revision only for plugins reading `delivered` or `error`; the last compatible version is API v2 shipped in Avi 0.9.0. Other Plugin API v2 namespaces are unchanged.
- **API version range and compatibility mode** — definitions accept optional `minApiVersion` (integer, default `apiVersion`, not greater than `apiVersion`). Avi supports `MIN_PLUGIN_API_VERSION`–`PLUGIN_API_VERSION` (currently v2–v2), exposed as `minApiVersion`/`apiVersion` on the factory argument and as `pluginApi: { minVersion, version }` in `plugins:list`. Plugins with `apiVersion` in range keep strict validation; a newer `apiVersion` with an in-range `minApiVersion` loads with unknown definition and settings fields, capabilities, contribution types, and contribution fields ignored and listed in the record's new `compatibilityWarnings` and `apiVersion` fields. The previous error "Plugin apiVersion must be 2" is replaced by specific retired/too-new messages. Compatibility: Backward compatible; supports API v2.
- **Plugin location** — packaged builds load and install plugins from `~/.aivax/plugins` instead of `$INSTALL_DIR/plugins`, and plugin context labels read `$HOME/.aivax/plugins/<id>`. Plugin storage and materialized context move with it and survive updates; legacy packages are migrated on startup. Compatibility: Backward compatible; supports API v2.
- **Theme control tokens** — theme CSS can set `--control-background`, `--control-background-hover`, `--control-text`, `--control-primary-background`, `--control-primary-text`, `--control-accent`, `--control-focus-ring`, `--control-radius`, and `--control-radius-multiline` to restyle buttons, dropdowns, toggles, and fields outside the chat; unset tokens derive from the existing surface and accent variables. Compatibility: Backward compatible; supports API v2.
- **Reserved built-in theme IDs** — `github`, `catppuccin`, `solarized`, `nord`, `tokyo-night`, and `darcula` are now reserved for built-in themes; a plugin contributing a theme with one of these IDs fails to load with the existing ID-conflict error. Rename the plugin theme to keep using it. Compatibility: Breaking in API v2's Canary theme revision only for plugins using those theme IDs; the last compatible version is API v2 shipped in Avi 0.8.0. Other theme IDs and the theme contract are unchanged.
- **Retry rejection semantics** — `ThreadHandle.retry()` now rejects when no eligible prompt or checkpoint exists instead of returning an idle handle after a successful no-op. Compatibility: Breaking behavior change in API v2's Canary retry revision; the last compatible silent-no-op behavior is API v2 shipped in Avi 0.6.0. This runtime supports API v2 only; successful and already-active retries keep their existing contract.
- **Bot Inbox and Activity contract** — removes `bot.workState.get()` and the old work-item/worker types in favor of `bot.inbox.list/reply/complete`, `bot.activity.list`, dated messages, attachments, and pendency-bound approvals. `bots.readState` reads the new data; `bots.manage` permits replies/completion without granting protected approvals. Compatibility: Breaking in API v2's Canary bot-domain revision; the last compatible old bot-work contract is API v2 shipped in Avi 0.6.0. This runtime still supports API v2 only; existing bot-work integrations must update. Other Plugin API v2 namespaces are unchanged.
- **Persisted user-stop provenance** — `MessageSnapshot.stoppedByUser` identifies messages aborted by an explicit user Stop action. Compatibility: Backward compatible; supports API v2.
- **Provider model instance identities** — `ModelConfig` snapshots now include Avi-managed `instanceId`; configured model `id` values may repeat and continue to be sent unchanged to inference, while catalog `ModelSnapshot.id` is qualified as `providerId:instanceId`. Compatibility: Backward compatible; supports API v2.

### Fixed
- **Provider removal and default models** — `provider.remove()` now also clears default model assignments that reference the removed provider, as removing a provider in Settings does. Model rules are kept. Compatibility: Backward compatible; supports API v2.
- **Tool interruption** — when a run is stopped, Avi no longer waits for a plugin tool's `execute()` to settle: the call is recorded as interrupted as soon as `context.signal` aborts. Any later result is discarded, and side effects continue unless the tool honors `context.signal`. Compatibility: Backward compatible; supports API v2.
- **Fork and activation lifecycle** — copied streaming messages become completed partial-response snapshots; bot activation clears the previous compaction summary and token counter when advancing its history boundary. Compatibility: Backward compatible; supports API v2.
- **Thread fork handles and checkpoints** — `ThreadHandle.fork()` returns a usable handle for the copied conversation and preserves hidden checkpoint boundaries without replaying compacted history. Compatibility: Backward compatible; supports API v2.
